# 決定

画面は、iPhone 17 の Safari（縦向き 402×874 CSS px）を主な対象にして整える。広い画面（60rem より広い）の並びは変えない。色とパレットは [ADR-0010](0010-design-system-0-4.md) のまま。寸法と指の操作の規則を足したので、デザインシステムの版を 0.5.0 にする。

## 1. 指の操作

1. **指の画面（`pointer: coarse`）では、押せる大きさをすべて 44px 以上にする。** ボタン・入力欄・選択欄・タブ・開閉の見出し・メニューの項目のどれも `--touch-target`（44px）。[ADR-0011](0011-passkey-first-and-compact-ui.md) の 3.3（標準 36px・詰めた部品 32px）を置き換え、`--touch-target-md`・`--touch-target-sm` をなくした。規則は `app.css` の 1 か所に置き、部品ごとの `@media (pointer: coarse)` の高さの指定は外した。
2. **文の中や行の中の小さな部品は、見た目 32px・押せる範囲 44px にする**（`.touch-inline`、`--touch-target-inline`）。「?」の説明、チップの「×」、トーストの「×」。見た目を 44px にすると行の高さが変わるため、透明な `::after` で押せる範囲だけを広げる。
3. **チェックボックスとラジオは 22px にし、ラベルの行を 44px にする。** ラベル全体で押せる。
4. **入力欄・選択欄・本文欄・見たまま編集の文字は 16px 以上にする。** 16px より小さいと、iOS の Safari はフォーカスしたときに画面を拡大する。これまで一覧の検索欄と本文欄は 14〜15px だった。利用者の拡大（ピンチ）は止めない（WCAG 1.4.4）。
5. **hover の見た目は `@media (hover: hover)` の中だけに書く。** 指の画面では、押したあとに hover の色が残るため。押している間の色（`:active`）は、どの画面でも出す。
6. **押したときの灰色の反転（`-webkit-tap-highlight-color`）を消し、`touch-action: manipulation` を付ける。** 押下の色は自前で出す。2 度押しでの拡大の待ち時間もなくす。
7. **入力の補助を欄ごとに指定する。** slug・パス・ID・URL・メールアドレスは自動の大文字化と自動修正を切る。タグ・検索・リンクの欄は、キーボードの確定キーの表示（`enterkeyhint`）を「完了」「検索」にする。

## 2. 画面の端とキーボード

1. **画面の端まで使う（`viewport-fit=cover`）。** 安全領域は `--safe-top`・`--safe-right`・`--safe-bottom`・`--safe-left`（`env(safe-area-inset-*)`）で受け、上部バー・画面の左右・下の操作バー・フッター・ダイアログの余白に足す。[アプリの外枠](../product/app-shell.md) の「`viewport-fit=cover` は使っていない」を改めた。
2. **ブラウザの枠の色を、上部バーの面の色に合わせる**（`theme-color`。ライト `bg-surface`、ダーク `bg-surface`）。manifest の色も同じ値にする。CSS の変数を読めない場所なので値を直接書き、正本とのずれは単体テストで確かめる。
3. **画面キーボードの高さを `--keyboard-inset` に入れる**（`src/lib/ui/viewport.ts`）。iOS の Safari は、キーボードが出てもレイアウトの高さを変えず、見えている範囲（`visualViewport`）だけを縮める。下に固定した部品はキーボードの下に隠れるので、`visualViewport` の高さとの差を測って `<html>` に書き、出ている間は `data-keyboard="open"` を付ける。120px より小さい差（アドレスバーの伸び縮み）と、拡大中（`scale` が 1 より大きい）は 0 とする。
4. **下に固定する部品は、`bottom: var(--keyboard-inset)` で置く。** キーボードが出ている間は、ホームインジケーターの分の余白（`--safe-bottom`）を足さない。

## 3. 狭い画面（60rem 以下）の編集画面

1. **「フォーム」を「本文」と「記事情報」のタブに分ける。** これまでは記事情報（タイトル・slug・日付・タグなど）の下に本文があり、本文まで 2 画面分スクロールしていた。タブは「本文｜記事情報｜Markdown｜プレビュー」。新しい記事は「記事情報」から、既存の記事は「本文」から始める。広い画面は「フォーム」のまま（本文と記事情報を横に並べる）。
2. **タブは、上部バーのすぐ下に固定する。** 長い本文の途中でも切り替えられる。
3. **記事の操作は、画面の下の操作バーに置く**（`[data-bottom-bar]`）。左から「保存」（幅を使う）、「元に戻す」「やり直す」（アイコン）、「…」（原文の退避・その他）。アイコンだけのボタンにも、読み上げ用の名前は残す。親指の届く位置で、キーボードが出ている間はその上に載る。操作バーの高さは `--bottom-bar-height` に入れ、本文の下の余白と、フォーカスした欄を見える位置へ送る余白（`scroll-padding-bottom`）に使う。
4. **頻度の低い操作は「…」に入れる。**「コミット…」「原文をコピー」「原文をダウンロード」「ディスクから再読み込み」「複製…」「削除…」「記事を閉じる」。メニューは上へ開く。未保存のときは「コミットは、保存してからできます。」と理由を出す。
5. **記事を閉じたら一覧に戻す。** 空の編集画面に残さない。
6. **状態の印（保存・原稿・Git）は 1 行にし、あふれたら横に送る。** 記事名は 2 行まで。

## 4. 見たまま編集の書式の帯

1. **指の画面では、書式の帯を画面の下に付ける**（操作バーの上。キーボードが出ている間はその上）。[ADR-0011](0011-passkey-first-and-compact-ui.md) の 3.5（カーソルの近くに浮かせる）は、マウスの画面だけに残す。iOS では、選択した文字の近くに OS のメニュー（コピー・調べるなど）が出て、浮かせた帯と重なるため。
2. **帯は 1 行で、あふれたら横に送る。** ボタンは 44px。リンクの入力欄は帯の中で折り返す。
3. **カーソルが帯や操作バーの下に隠れないよう、選択が変わるたびに見える位置へ送る。**

## 5. ダイアログ・メニュー・通知

1. **30rem 以下では、ダイアログを画面の下から出すシートにする。** 幅は画面いっぱい、上の角だけ丸め、高さは上部バーの分を残す。キーボードが出ている間はその上に載る。ボタンは縦に並べ、幅いっぱいにする。
2. **メニューは、30rem 以下では画面の幅いっぱいに開く。** 高さは安全領域とキーボードの分を引く。
3. **トースト（保存した、などの通知）は、上部バーのすぐ下に出す。** これまでの右下は、書式の帯・操作バー・キーボードと重なる。
4. **作業場所の書き出しの帯は、30rem 以下では文を左、「書き出す…」を右に置く。** これまでは 2 段になり、画面の 1/5 を使っていた。

## 6. 言葉

「ロック」「ロック解除」は [ADR-0014](0014-lock-unlock-wording-and-no-backward-compat.md) のまま変えない。そのほかの画面の言葉を、次の規則でそろえた。

1. **同じ操作は同じ言葉にする。**

   | これまで | これから | 理由 |
   |---|---|---|
   | 読み込み直す・読み直す | 再読み込み | 「再読み込み」と合わせて 3 通りあった |
   | フォルダを選択 | フォルダを開く | メニューの「別のフォルダを開く」と合わせる |
   | 状態（一覧の絞り込み） | 原稿状態 | 保存の状態・Git の状態と区別する |
   | 復旧退避（編集画面の状態の行） | 復旧ドラフト | メニュー・設定の名前と合わせる |
   | 原文を退避（復旧ドラフトの一覧） | 原文をダウンロード | 編集画面の同じ操作の名前と合わせる |
   | 最後のリポジトリ保存 | 最後の保存 | 「保存」はほかに無い |
   | このセッションでは未保存 | 開いてからは未保存 | 「セッション」を画面に出さない |
   | 本CMS | CMS | 書き言葉をやめる |
   | カバーにする | カバー画像にする | 項目の名前「カバー画像」と合わせる |
   | 外す（リンク） | リンクを外す | 何を外すかを書く |
   | 取得（pull） | 取得する（pull） | 動詞にする |
   | 閉じる（狭い画面の「…」の中） | 記事を閉じる | メニューを閉じる操作と区別する |

2. **確認や入力の窓を開くボタンは、名前の最後に「…」を付ける。**「コミット…」「削除…」「書き出す…」「Git を初期化…」。押してすぐ実行するボタンには付けない。
3. **状態の行は「名前：値」の形にする。**「復旧ドラフト：退避済み（12:34）」「最後の保存：12:30:05（3分前）」「原稿状態：下書き」。
4. **空の状態には、次にできることを書く。**「記事はまだありません。「新規作成」から始められます。」
5. **内部の言葉を画面に出さない。**「メタデータ未取得」は「まだ読み込んでいません」。
6. **日数が 0 のときは書かない。**「書き出し・同期していない変更あり（3 日前から）」。当日なら括弧ごと出さない。
7. **仕様の用語は変えない。**「復旧ドラフト」「公開対象」「初回フォルダ準備」。

# 理由

- 依頼により、主な対象を iPhone 17 の Safari にする。これまでの画面は 1280 幅で設計し、狭い画面は並べ替えるだけだった。402 幅で測ると、操作列が 3 段に折り返す、押せる高さが 27〜36px、本文が記事情報の下に埋もれる、通知がメニューの開閉と重なる、という問題があった。
- 押せる大きさを部品の種類で分ける規則（ADR-0011）は、WCAG 2.5.8（24px）を満たすが、iPhone では Apple の 44pt が基準になる。主な対象を iPhone にしたので、1 つの値にそろえた。規則が 1 つになり、部品ごとの指定も要らなくなる。
- 画面キーボードは画面の下 4 割ほどを覆う。保存と書式を画面の上に置くと、書いている間は届かない。下に置き、キーボードに追従させる。
- 言葉は、同じ操作に 2〜3 通りの名前があると、別の操作に見える。

# 影響と注意

- **マウスの画面（`pointer: fine`）の大きさは変わらない。** 44px の規則は指の画面だけ。狭い画面の並び（タブ・操作バー）は、マウスの画面でも幅が 60rem 以下なら同じになる。
- **E2E の `data-testid` は変えていない。** 狭い画面では `tab-form` の代わりに `tab-body`・`tab-meta` が出る。「コミット…」「削除…」は「…」の中に移るが、`commit-button`・`delete-button` のまま。
- **`tests/e2e/iphone.spec.ts` を足した。** 402×874・タッチで、どの画面でも押せる部品が 44px 以上・入力欄が 16px 以上・横スクロールなし、を確かめる。キーボードと安全領域は、ヘッドレスの Chromium では起きないので、`--keyboard-inset`・`--safe-top`・`--safe-bottom` を書いて代わりにする。
- 既存の E2E と単体テストの文言を、新しい言葉に合わせた。

# 確かめていないこと

実機の iPhone 17 の Safari では確かめていない。確認は、ヘッドレスの Chromium を 402×874・タッチにした画面だけ。次の点は実機で見る必要がある。

- キーボードが出入りするときに、下の操作バーと書式の帯が遅れずに付いてくるか（`visualViewport` の通知の頻度による）。
- 書式の帯のボタンを押したときに、フォーカスが本文に残り、キーボードが閉じないか。
- iOS 26 の Safari の浮いたツールバー（アドレスバー）と、下の操作バーが重ならないか。ホーム画面から開いたとき（standalone）の上の余白。
- 横向き（左右の安全領域）と、文字を大きくする設定（Dynamic Type）での並び。
- VoiceOver での、タブ・「…」・シートの読み上げとフォーカスの移り方。

# 未決・残る課題

- 仕様 3.2 の第14章（画面と操作）への反映は別に行う。
- 一覧から記事を開く・閉じるときの動き（横に送るなど）は付けていない。
- 「原文の退避・その他」の名前。短くしたいが、退避の案内の文がこの名前を指しているため、いまは変えていない。
