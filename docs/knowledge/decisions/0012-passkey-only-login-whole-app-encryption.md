# 決定

[ADR-0011](0011-passkey-first-and-compact-ui.md) の第1章を次のように改める。

## 1. ログインはパスキーだけ

1. **登録・ログインはパスキー（PRF）だけ。** パスフレーズでの登録・ログイン・設定はなくす。以前の版で作ったパスフレーズの枠は、ログインしたときにログインの記録から外す。
2. **回復コードは残す。** 登録の直後に一度だけ表示する。パスキーを使えないとき（別の端末・削除・取り消し）は回復コードでログインする。回復コードでログインしたあと、この配信元で使えるパスキーがなければ、パスキーの登録を求める（登録するまで使い始めない）。配信元を移したときも同じ道で登録し直す。
3. **file:// では使えない。** `file://` には RP ID（ホスト名）がなく、ブラウザがパスキーを使わせない。ファイルを直接開いたときは、https の配信元（GitHub Pages など）か localhost から開くよう案内するだけにし、登録・ログイン・フォルダの選択はできない（利用者の選択）。デスクトップでも https の配信元から開けば、実フォルダを選んで編集できる（Chrome・Edge の File System Access API）。
4. **ログインを作り直すと、ログインの鍵で暗号化したものはすべて読めなくなる。** 復旧ドラフトは削除する。作業場所は自動では消さず、「このログインでは開けない」と示して削除だけできるようにする。

## 2. アプリ全体をログインの鍵で暗号化する

1. **ブラウザ内の作業場所は常に暗号化する。** 作成・取り込みで「暗号化する」の選択をなくした。作業場所ごとのデータ鍵（DK、32 バイトの乱数）は残し、ログインの鍵で包んで作業場所の meta に置く（鍵の枠の種類 `login`。追加認証データに作業場所 ID を含め、別の作業場所の枠への差し替えでは開けない）。
2. **作業場所ごとの回復コード・パスフレーズ・パスキーはない。** 作成時に回復コードを表示しない。「設定」の作業場所の解錠の方法（パスフレーズ・パスキーの登録・外す）と、作業場所ごとのロックをなくした。ロックはアプリのロック（ログインの画面に戻る）だけ。
3. **以前の版の作業場所は失わない。** 作業場所の回復コード等の枠を持つ作業場所は、その回復コードで一度解錠すると、meta にログインの枠を足し、次からはログインだけで開ける（元の枠も残す）。ADR-0011 でログインの記録（IndexedDB）に覚えていた作業場所の鍵は、ログインしたときに meta のログインの枠へ移し、ログインの記録から外す。暗号化しない以前の作業場所は、そのまま開ける。
4. **ログインの記録と作業場所の鍵の置き場所を分けない。** 作業場所の鍵は作業場所の meta（OPFS）にあり、ログインの記録（IndexedDB）には包んだログインの鍵だけを置く。

## 3. 暗号化した書き出し（.kotono）の版 2

1. **ヘッダーの版 2** に、DK を直接包んだ枠（以前の版の作業場所の回復コード等。なければ空）と、書き出した端末のログインの枠（回復コード・パスキー。パスフレーズの枠は入れない）・ログインの鍵で包んだ DK を入れる。先頭の `KOTONO-EXPORT/1` は変えない。本文の追加認証データはヘッダー全体（改ざんを検出する）。
2. **同じ端末（同じログイン）では、回復コードを求めずに取り込める。** 別の端末では、書き出した端末のログインの回復コードで開く。同期したパスキー（iCloud キーチェーン等で同じ配信元）なら、パスキーでも開ける見込み（未確認）。
3. **取り込んだ作業場所は、取り込んだ端末のログインの鍵で包む。** DK は書き出しと同じ。
4. **版 1 の書き出しも開ける**（作業場所の回復コード・パスフレーズ・パスキー）。

# 理由

- 起動時に一度パスキーで認証すれば、作業場所ごとに鍵の方法を管理する理由がない。回復コードの控えも 1 つで済む。
- 作業場所の鍵を作業場所の meta に置けば、ログインの記録と作業場所の対応がずれない（作業場所だけを消した・記録だけが残った、が起きない）。
- パスフレーズは推測・使い回しに弱く、パスキーと回復コード（125 ビットの乱数）で足りる。

# 影響と注意

- **file:// で直接開く使い方はできなくなった。** README の「デスクトップは file:// で開く」を改めた。E2E は dist を localhost から配信し、Chromium の仮想の認証器（PRF 対応）で登録・ログインする。
- **以前の版の CMS で、この版で作った作業場所を開くと「鍵の情報が不正」として不完全と表示する**（鍵の枠 `login` を知らないため）。中身は消さない。版 2 の書き出しも以前の版では開けない。
- **ログインの回復コードの重みが増えた。** パスキーと回復コードの両方を失うと、復旧ドラフトだけでなく、ブラウザ内の作業場所も誰も戻せない。書き出し・GitHub との同期が唯一の外の控えになる。
- **書き出しには、書き出した端末のログインの枠が入る。** 書き出しと回復コードの両方を得た人は、そのログインの鍵も得る。その鍵で開けるのはその端末の作業場所の meta の枠だけで、端末の保存領域がなければ使えない。

# 未決・残る課題

- 実機（iPhone・iPad の Safari、Windows Hello・Touch ID の Chrome・Edge）でのパスキーの登録・PRF・ログインは未確認。確認はヘッドレス Chromium の仮想の認証器だけ。
- 同期したパスキーで別の端末の書き出しを開けるか（端末間で PRF の出力が同じか：TG14）は未確認。
- file:// の案内には配信元の URL を出していない（配信元が決まったら出す）。
- 仕様 39 章（作業場所ごとの鍵）・39.3（起動時のログイン）の改訂は、この ADR を正とし、仕様書への反映は別に行う。
