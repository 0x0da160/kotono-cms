# 決定

> 第1章のうち、パスフレーズ（1.3）・作業場所ごとの鍵（1.5）・作り直し（1.7）は [ADR-0012](0012-passkey-only-login-whole-app-encryption.md) で置き換えた。

## 1. 起動時のログイン（何よりも先に）

1. **最初にパスキーを登録し、以後は起動するたびにパスキーで認証してから使う。** サーバーへのログインではなく、端末内の「ログイン鍵」（32 バイトの乱数）をパスキーの PRF で開く操作（[ADR-0006](0006-ios-safari-git-plan.md) 第7章と同じ方式）。フォルダの選択・作業場所の一覧より前に出す。
2. **回復コードの枠を必ず作る。** 登録の直後に一度だけ表示し、保存を確かめてから使い始める（作業場所の回復コードと同じ画面の部品）。パスキーが使えないとき（別の端末・取り消し）は回復コードでログインできる。失敗しても自動では繰り返さない。
3. **パスキーを使えない開き方では、パスフレーズで同じことをする。** `file://` には RP ID（ホスト名）がなく WebAuthn を使えないため、パスフレーズ（10 文字以上）で登録・ログインする。パスキーを使える開き方でも、パスフレーズを選べる（PRF に対応しない管理アプリのため）。
4. **記録はブラウザ内に 1 件。** IndexedDB（`kotono-cms-settings` の `login`）に、包んだログイン鍵の枠（作業場所の `KeyringRecord` と同じ形・同じ検査）と、ログイン鍵で包んだ作業場所の鍵を置く。ログイン鍵そのものは保存せず、ロックで捨てる。
5. **暗号化した作業場所は、ログインだけで開ける。** 作成・取り込み・解錠のときに、その作業場所のデータ鍵をログイン鍵で包んで覚える（追加認証データに作業場所 ID）。以前の作業場所は、一度その回復コード等で解錠すると次から覚える。作業場所の meta の形式は変えない（古い版で開いても壊れない）。
6. **ロック・自動ロックはログインに戻す。** メニューの「ロック」と、作業場所の自動ロック（無操作の時間）は、作業場所をロックしてからログイン鍵も捨てる。未保存の編集は先に復旧ドラフトへ退避する。
7. **どの方法でもログインできないときは作り直せる。** ログインの記録を消し、このブラウザの復旧ドラフトをすべて削除する（もう読めないため）。作業場所は消さない。

## 2. 復旧ドラフト

1. **既定で有効。** 事前の同意の画面（仕様 33.1）をやめ、未設定は有効として扱う。「設定」の「復旧ドラフト」で無効にでき、無効にしたら無効のまま。
2. **すべて暗号化する。** 実フォルダ・暗号化しない作業場所のドラフトもログイン鍵で包む（キーとチェックサムは HMAC、本文・記事 ID・元のハッシュは AES-GCM）。暗号化した作業場所のドラフトはこれまで通り作業場所の鍵で包む。ログインしていない間は読み書きしない。
3. **以前の版の平文のドラフトは、ログインしたときに包み直す。**

## 3. 画面

1. **上部バーは固定し、スクロールで詰める。** 狭い画面はページ全体、広い画面は一覧・編集の領域のスクロールで、上下の余白と文字を詰め、説明文を外す（24px より下で詰め、4px より上で戻す）。ページ全体がスクロールするときは、縮んだ高さの分を上部バーの下の余白に足してページの高さを保つ（2026-11-09：説明文のある最初の画面では高さが 30〜60px 変わり、スクロールの位置が戻って詰める・戻すを繰り返していた）。固定した上部バーの下に部品が隠れないよう `scroll-padding-top` を足す。
2. **画面の切り替えはメニュー（ハンバーガー）にまとめる。** 右端の「メニュー」に、画面（記事／一覧・編集／Git と同期／設定）・場所の操作・ヘルプ・ロックを置く。開閉は `aria-expanded`、Esc と外側の押下で閉じて開閉のボタンへ戻る。いまの画面の名前はアプリ名の横に出す。
3. **指の画面の押せる高さを、部品の種類ごとの規則にする**（`app.css` の表）。

   | 部品 | 下限 | 準拠する規則 |
   |---|---|---|
   | メニューの項目・メニューの開閉 | 44px | Apple HIG（44pt）。画面の端で頻繁に押す |
   | 標準のボタン・入力欄・選択欄 | 36px | WCAG 2.2 の 2.5.8（AA：24px）に余裕を足す |
   | 詰めたボタン（道具の帯・行の中）・開閉の見出し | 32px | WCAG 2.2 の 2.5.8 |
   | チェックボックス・ラジオ | 20px | 2.5.8 の例外（ラベル全体で押せる） |

   これまでの 44px は WCAG 2.5.5（AAA）・Apple HIG の値を全部品に当てていた。AA の 2.5.8 は 24px（または間隔）で満たすので、移動のための部品だけに残した。
4. **表の形の並びに罫線を引く。** 項目名と値の並び（Git の状態・記事 ID と日時）、対応環境の確認の一覧、競合の比較の表、プレビューの表の見出しの面。見たまま編集の表（GFM）は、編集できない塊のまま罫線つきの表として見せる（元の記述は変えない）。
5. **見たまま編集の書式の帯を、カーソル（選択範囲）の上に出す。** 上に場所がなければ下。本文にフォーカスがある間だけ出す。「見出し2・見出し3・段落・太字・斜体・リンク」を並べ、ほか（取り消し線・コード・箇条書き・番号付き・引用・コードブロック）は「その他」に入れる。Alt+F10 で帯へ、Esc で本文へ戻る。

# 理由

- パスキーの認証を作業場所ごとにしていたため、作業場所が増えると認証の候補と手間が増え、作業場所を作る前は何も守られていなかった。起動時に 1 回認証すれば、復旧ドラフトと作業場所の鍵の両方を開ける。
- 暗号化しない復旧ドラフトは、事前の同意（共有の端末では有効にしない）が要った。ログイン鍵で暗号化すれば、既定で有効にしても本文がブラウザの保存領域に平文で残らない。

# 未決・残る課題

- 実機（iPhone・iPad の Safari、Windows Hello・Touch ID の Chrome・Edge）でのパスキーの登録・PRF・ログインは未確認。確認はヘッドレス Chromium の仮想の認証器だけ。
- `file://` のパスフレーズは、起動のたびに入力する（Chrome は `file://` のパスワードを保存しないことがある）。
- 実フォルダ（デスクトップ）では自動ロックをしない（ロックはメニューから）。
- 書式の帯の位置は、iOS の画面キーボードが出ている間の見え方を実機で確かめていない。
- 仕様 33.1（事前の同意）・39.3（起動時のログイン）の改訂は、この ADR を正とし、仕様書への反映は別に行う。
