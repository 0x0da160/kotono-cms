# アプリの外枠（シェル）

色・文字・余白は [デザインシステム](design-system.md) のトークンを使う。この文書は、その上に載る「どこに何を置くか」と「どう移るか」を決める。実装は `src/App.svelte`。

## 決定

1. **画面は3つ**：「記事」「Git と同期」「設定」。フォルダ（作業場所）を開くと、上部バーで切り替える。ヘルプは画面ではなくダイアログで、上部バーから開く。
2. **切り替えても閉じない**：隠れた画面は表示を止める（`hidden`）だけで、部品は残す。編集中の内容・取り消し履歴・スクロール位置・入力中の同期設定は、切り替えで失われない。未保存の確認も出さない。
3. **広い画面（60rem より広い）**：画面全体の高さで作業する。上部バーとお知らせの帯は動かず、「記事」は一覧と編集がそれぞれスクロールする（UI刷新 方向B のまま）。
4. **狭い画面（60rem 以下）**：ページ全体を1つのスクロールにし、上部バーの2行目に「一覧｜編集｜Git と同期｜設定」を並べる。これまで本文の上にあった「一覧・編集」の切り替えは、ここにまとめた。
5. **最初の画面**（フォルダを開く前・作業場所を選ぶ前）は切り替えを出さない。版の表示と復旧ドラフトの設定はフッターに置く（これまで通り）。

### なぜこの形か

- これまでは、Git の状態と GitHub との同期が**記事一覧の下**にあり、一覧が長いと見つからなかった。復旧ドラフトの設定・ヘルプ・版は**フッター**にあり、作業中は画面の最下部の細い帯だった。機能の置き場所を、用途ごとの画面に分けた。
- 記事単位のコミットは編集画面の「コミット…」と一覧の状態の表示で足りる。「Git と同期」の画面は、リポジトリ全体の状態・履歴・GitHub との送受信に使う。
- 画面を3つより増やさない。左の縦のナビゲーションは、3項目では横の幅を使いすぎる（1280 幅で本文の幅が減る）ので採らない。
- 狭い画面で切り替えを2段（画面の切り替えと、一覧・編集の切り替え）にしない。1段 4 項目にすると、iPhone の縦（390px）でも 1 行に収まり、指で押せる高さ（44px）を保てる。

## 領域

```
┌ 上部バー ─────────────────────────────────────────────┐
│ Kotono CMS  [記事][Git と同期][設定]   作業フォルダ：x  [別のフォルダを開く] [ヘルプ] │
└───────────────────────────────────────────────────────┘
  お知らせの帯（あるときだけ）：新しい版・作業場所の書き出し状態・フォルダや設定の問題・Git の結果
┌ 画面 ──────────────────────────────────────────────────┐
│ 記事：一覧 │ 編集（見出し・状態・操作列は固定、本文｜記事情報）          │
│ Git と同期：Git の状態・変更・履歴、GitHub との同期（幅 48rem）            │
│ 設定：復旧ドラフト、解錠の方法と自動ロック（作業場所）、このアプリについて（幅 48rem） │
└───────────────────────────────────────────────────────┘
  通知（トースト）：画面の下に重ねる（Editor の保存・警告。位置は変えない）
```

| 領域 | 中身 | 出す条件 |
|---|---|---|
| 上部バー | アプリ名（最初の画面だけ説明文も）、画面の切り替え、開いている場所の名前、場所の操作（別のフォルダを開く／作業場所の一覧・ロック）、ヘルプ | 常に |
| お知らせの帯 | 新しい版の案内、作業場所の書き出し・同期の状態と「書き出す」、フォルダ・設定ファイルの問題、Git の結果（「Git と同期」の外にいるとき） | フォルダ（作業場所）を開いた後、出すものがあるとき |
| 画面「記事」 | 復旧ドラフトの候補、記事一覧、編集、初回の復旧ドラフトの同意（編集側の列） | 記事フォルダがあるとき |
| 画面「Git と同期」 | Git パネル、GitHub との同期 | 同上 |
| 画面「設定」 | 復旧ドラフトの設定、解錠の方法と自動ロック（暗号化した作業場所）、版と更新の確認 | 同上 |
| フッター | 復旧ドラフトの設定（畳む）、版と更新の確認 | 最初の画面と、記事フォルダの準備の画面 |

- 上部バーは `--color-surface` の面と下の罫線で、画面（`--color-bg`）と分ける。
- 「Git と同期」「設定」は文章と入力欄が中心なので、幅を 48rem に絞って中央に置く。
- 上部バーの中身の左右の端は、画面の中身の最大幅（96rem）にそろえる。

## 画面の切り替え

- `<nav aria-label="画面の切り替え">` の中のボタン。いまの画面は `aria-current="page"`。見た目は**文字の太さと下線**で示し、色だけに頼らない（仕様 14.1）。
- 広い画面：「記事」「Git と同期」「設定」。狭い画面：「一覧」「編集」「Git と同期」「設定」。使わない方は `display: none` で、読み上げにも出さない。
- 「編集」は記事を開いていないとき押せない。一覧で記事を開くと「編集」に移る。
- フォルダ（作業場所）を開き直すと「記事」（狭い画面では「一覧」）に戻る。
- アイコンは文字に添えるだけ。30rem 以下ではアイコンを外し、文字を残す。

### フォーカスと通知

- 初回の復旧ドラフトの同意を閉じたら、最初の画面ではフッターの「復旧ドラフト」、作業中は上部バーの「設定」へフォーカスを移し、「設定から変えられる」ことを読み上げる（UI刷新 P-04 の考え方を引き継ぐ）。
- Git の結果（コミットした・できなかった）は「Git と同期」の画面の先頭に出す。その画面を見ていないときは、お知らせの帯に1行で出し、「「Git と同期」で見る」と「閉じる」を付ける。編集画面からコミットしても結果が見える。
- スキップリンク「本文へ移動」は `main` へ移る（変更なし）。

## 狭い画面と iPhone・iPad

| 幅 | 上部バー | 画面 |
|---|---|---|
| 60rem より広い | 1 行：アプリ名・切り替え・場所・ヘルプ | 画面の高さに固定し、領域ごとにスクロール |
| 30rem〜60rem（iPad の縦など） | 1 行目：アプリ名・場所・ヘルプ、2 行目：切り替え（4 つを同じ幅） | ページ全体でスクロール。一覧と編集は1度に1つ |
| 30rem 以下（iPhone の縦） | 1 行目：アプリ名・ヘルプ、2 行目：場所とその操作、3 行目：切り替え（文字だけ） | 同上 |

- 指で操作する画面のボタンの高さ 44px 以上と、入力欄の文字 16px 以上は `app.css` の規則のまま。
- 上部バーは狭い画面で固定しない。編集の見出し・操作列の固定（広い画面）と重ならないようにするためと、iPhone では縦の領域が少ないため。
- `viewport-fit=cover` は使っていない（安全領域の余白は要らない）。使うときは、上部バーとフッターに `env(safe-area-inset-*)` の余白を足す。

## 確かめていないこと

- 実機（iPhone・iPad の Safari、Windows・macOS の Chrome・Edge）での表示。確認はヘッドレス Chromium の 1280×800・900×800・iPhone 13 相当の画面だけ。
- 実際の利用者が「Git と同期」「設定」を見つけられるか（発見性）。
