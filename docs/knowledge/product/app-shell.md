# アプリの外枠（シェル）

色・文字・余白は [デザインシステム](design-system.md) のトークンを使う。この文書は、その上に載る「どこに何を置くか」と「どう移るか」を決める。実装は `src/App.svelte`。

## 決定

1. **何よりも先にログイン**：起動するとまずパスキーの登録（初回）か認証（2 回目以降）を求める。パスキーを使えない開き方（`file://`）ではパスフレーズ。ログインするまで、フォルダの選択・作業場所の一覧は出さない（[ADR-0011](../decisions/0011-passkey-first-and-compact-ui.md)）。
2. **画面は3つ**：「記事」「Git と同期」「設定」。フォルダ（作業場所）を開くと、上部バーの右端の「メニュー」から切り替える。ヘルプは画面ではなくダイアログで、メニューから開く（ログインの前は上部バーの「ヘルプ」）。
3. **切り替えても閉じない**：隠れた画面は表示を止める（`hidden`）だけで、部品は残す。編集中の内容・取り消し履歴・スクロール位置・入力中の同期設定は、切り替えで失われない。未保存の確認も出さない。
4. **上部バーは固定し、スクロールで詰める**：画面の上に残し（`position: sticky`）、スクロールしたら上下の余白と文字を詰める。説明文は外す。広い画面では一覧・編集の領域のスクロール、狭い画面ではページのスクロールで判定する。詰めて縮んだ高さの分は上部バーの下の余白に足し、ページの高さを変えない（変えるとスクロールの位置が戻り、詰める・戻すを繰り返してちらつく）。メニューの開閉はアイコン（≡）だけにし、名前「メニュー」は読み上げ（`aria-label`）とツールチップ（`title`）で伝える。
5. **広い画面（60rem より広い）**：画面全体の高さで作業する。「記事」は一覧と編集がそれぞれスクロールする（UI刷新 方向B のまま）。
6. **狭い画面（60rem 以下）**：ページ全体を1つのスクロールにし、メニューの画面の項目を「一覧｜編集｜Git と同期｜設定」にする。
7. **最初の画面**（フォルダを開く前・作業場所を選ぶ前）は画面の切り替えを出さない。メニューにはヘルプとロックだけ。版の表示と復旧ドラフトの設定はフッターに置く。

### なぜこの形か

- 画面の切り替えを上部バーに並べると、狭い画面では2行目を使い、縦の領域を圧迫していた。メニューにまとめ、上部バーを1行にした。いまの画面の名前はアプリ名の横に出して、メニューを開かなくても分かるようにした。
- 画面を3つより増やさない。左の縦のナビゲーションは、3項目では横の幅を使いすぎる（1280 幅で本文の幅が減る）ので採らない。

## 領域

```
┌ 上部バー（固定・スクロールで詰める）────────────────────────────┐
│ Kotono CMS │記事   作業フォルダ：x       [≡] │
└───────────────────────────────────────────────┘
                     メニュー：画面（記事｜Git と同期｜設定）／場所（別のフォルダを開く・作業場所の一覧）／ヘルプ／ロック
  お知らせの帯（あるときだけ）：新しい版・作業場所の書き出し状態・フォルダや設定の問題・Git の結果
┌ 画面 ──────────────────────────────────────────┐
│ ログイン（ログインするまで、ほかの画面の代わりに出す）                    │
│ 記事：一覧 │ 編集（見出し・状態・操作列は固定、本文｜記事情報）          │
│ Git と同期：Git の状態・変更・履歴、GitHub との同期（幅 48rem）            │
│ 設定：アプリの更新と版、復旧ドラフト、ログイン、解錠の方法と自動ロック（作業場所）（幅 48rem） │
└───────────────────────────────────────────────┘
```

| 領域 | 中身 | 出す条件 |
|---|---|---|
| 上部バー | アプリ名（最初の画面だけ説明文も）、いまの画面の名前、開いている場所の名前、メニュー | 常に（ログインの前はメニューの代わりにヘルプ） |
| メニュー | 画面の切り替え、場所の操作（別のフォルダを開く／作業場所の一覧）、ヘルプ、ロック | ログインの後 |
| ログイン | パスキーの登録（使えなければパスフレーズ）・回復コードの保存、2 回目からはパスキー・パスフレーズ・回復コードでのログイン | ログインするまで |
| お知らせの帯 | 新しい版の案内、作業場所の書き出し・同期の状態と「書き出す」、フォルダ・設定ファイルの問題、Git の結果（「Git と同期」の外にいるとき） | フォルダ（作業場所）を開いた後、出すものがあるとき |
| 画面「記事」 | 復旧ドラフトの候補、記事一覧、編集 | 記事フォルダがあるとき |
| 画面「Git と同期」 | Git パネル、GitHub との同期 | 同上 |
| 画面「設定」 | 版と更新の確認、復旧ドラフトの設定（既定で有効）、ログインの方法、解錠の方法と自動ロック（暗号化した作業場所） | 同上 |
| フッター | 復旧ドラフトの設定（畳む）、版と更新の確認 | 最初の画面と、記事フォルダの準備の画面 |

- メニューの「ロック」・自動ロックは、ログインの画面に戻す。ログインすると、覚えている暗号化した作業場所は解錠済みになる。
- 「Git と同期」「設定」は文章と入力欄が中心なので、幅を 48rem に絞って中央に置く。

## 画面の切り替え

- 上部バーの「メニュー」（`aria-expanded`・`aria-controls`）で開く `<nav aria-label="メニュー">` の中のボタン。いまの画面は `aria-current="page"`。見た目は**文字の太さと左の線**で示し、色だけに頼らない（仕様 14.1）。
- 開くと最初の項目へフォーカスを移す。Esc・外側の押下・項目の選択で閉じ、開閉のボタンへ戻す。
- 広い画面：「記事」「Git と同期」「設定」。狭い画面：「一覧」「編集」「Git と同期」「設定」。使わない方は `display: none` で、読み上げにも出さない。
- 「編集」は記事を開いていないとき押せない。一覧で記事を開くと「編集」に移る。
- フォルダ（作業場所）を開き直すと「記事」（狭い画面では「一覧」）に戻る。

### フォーカスと通知

- ログインの画面が消えたら、画面の中身（`main`）へフォーカスを移す。
- Git の結果（コミットした・できなかった）は「Git と同期」の画面の先頭に出す。その画面を見ていないときは、お知らせの帯に1行で出し、「「Git と同期」で見る」と「閉じる」を付ける。
- スキップリンク「本文へ移動」は `main` へ移る（変更なし）。

## 狭い画面と iPhone・iPad

| 幅 | 上部バー | 画面 |
|---|---|---|
| 60rem より広い | 1 行：アプリ名・いまの画面・場所・メニュー | 画面の高さに固定し、領域ごとにスクロール |
| 30rem〜60rem（iPad の縦など） | 同じ 1 行。上部バーは固定し、スクロールで詰める | ページ全体でスクロール。一覧と編集は1度に1つ |
| 30rem 以下（iPhone の縦） | 1 行：アプリ名・いまの画面・メニュー（場所の名前は外す） | 同上 |

- 指で押せる高さは部品の種類で分ける（`app.css` の表、[ADR-0011](../decisions/0011-passkey-first-and-compact-ui.md)）。メニューの項目と開閉は 44px（Apple HIG）、標準の部品は 36px、詰めた部品は 32px（WCAG 2.5.8）。入力欄の文字は 16px 以上。
- 固定した上部バーの下にフォーカスした部品が隠れないよう、狭い画面では `scroll-padding-top` に上部バーの高さを足す。
- `viewport-fit=cover` は使っていない（安全領域の余白は要らない）。使うときは、上部バーとフッターに `env(safe-area-inset-*)` の余白を足す。

## 確かめていないこと

- 実機（iPhone・iPad の Safari、Windows・macOS の Chrome・Edge）での表示。確認はヘッドレス Chromium の 1280×800・900×800・iPhone 13 相当の画面だけ。
- 実際の利用者が「Git と同期」「設定」を見つけられるか（発見性）。
