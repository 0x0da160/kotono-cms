# アプリの外枠（シェル）

色・文字・余白は [デザインシステム](design-system.md) のトークンを使う。この文書は、その上に載る「どこに何を置くか」と「どう移るか」を決める。実装は `src/App.svelte`。

## 決定

1. **何よりも先にロック解除**：起動するとまずパスキーの登録（初回）か認証（2 回目以降）を求める。パスキーを使えない開き方（`file://`）では使えず、https の配信元か localhost から開くよう案内する（[ADR-0012](../decisions/0012-passkey-only-login-whole-app-encryption.md)）。ロックを解除するまで、フォルダの選択・作業場所の一覧は出さない（[ADR-0011](../decisions/0011-passkey-first-and-compact-ui.md)）。ロック解除の画面でも、上部バーとメニューは出す（[ADR-0013](../decisions/0013-header-menu-consolidation.md)）。この操作は「ログイン」と呼ばず、「ロック」と「ロック解除」の対で表す（[ADR-0014](../decisions/0014-lock-unlock-wording-and-no-backward-compat.md)）。
2. **画面は3つ**：「記事」「Git と同期」「設定」。フォルダ（作業場所）を開くと、上部バーの右端の「メニュー」から切り替える。場所・復旧ドラフト・対応環境の確認・ヘルプ・ロックも、同じメニューに置く。
3. **切り替えても閉じない**：隠れた画面は表示を止める（`hidden`）だけで、部品は残す。編集中の内容・取り消し履歴・スクロール位置・入力中の同期設定は、切り替えで失われない。未保存の確認も出さない。
4. **上部バーは最初からコンパクトで、大きさを変えない**：画面の上に固定し（`position: sticky`）、どの画面でも同じ高さにする。スクロールで縮めない（[ADR-0013](../decisions/0013-header-menu-consolidation.md)。ADR-0011 の縮小は取りやめた）。説明文は置かない。メニューの開閉はアイコン（≡）だけにし、名前「メニュー」は読み上げ（`aria-label`）とツールチップ（`title`）で伝える。
5. **広い画面（60rem より広い）**：画面全体の高さで作業する。「記事」は一覧と編集がそれぞれスクロールする（UI刷新 方向B のまま）。
6. **狭い画面（60rem 以下）**：ページ全体を1つのスクロールにし、メニューの画面の項目を「一覧｜編集｜Git と同期｜設定」にする。主な対象は iPhone 17 の Safari（402×874）で、編集画面は「本文」「記事情報」のタブと、画面の下の操作バーに分ける（[ADR-0015](../decisions/0015-iphone-17-safari-first-ui.md)。下の「狭い画面と iPhone・iPad」）。
7. **メニューの中身は、ロックと画面の状態で変わる**（下の「メニューの中身」）。最初の画面（フォルダを開く前・作業場所を選ぶ前）には画面の切り替えを出さない。版の表示と復旧ドラフトの設定はフッターに置く（設定の画面にも同じものを置く）。
8. **作業場所の操作は行の中にまとめる**：「書き出す」「削除」は、行の「…」を開いたときに出す。作業場所があるときは、「新しい作業場所・取り込み…」を折り畳む。
9. **保存領域を消さないよう求めた結果を示す**：押すと確認の間は押せなくし、結果（許可された・許可されなかった・この環境では求められない）を1行で出す。

### なぜこの形か

- 画面の切り替えを上部バーに並べると、狭い画面では2行目を使い、縦の領域を圧迫していた。メニューにまとめ、上部バーを1行にした。いまの画面の名前はアプリ名の横に出して、メニューを開かなくても分かるようにした。
- 上部バーは、最初から小さく固定して大きさを変えない。スクロールで縮めると画面が動いて見え、目障りになるため（[ADR-0013](../decisions/0013-header-menu-consolidation.md)）。説明文は上部バーから外した（README に残る）。
- 画面を3つより増やさない。左の縦のナビゲーションは、3項目では横の幅を使いすぎる（1280 幅で本文の幅が減る）ので採らない。

## 領域

```
上部バー（固定・大きさは変えない）   Kotono CMS ｜ 記事 ｜ 作業フォルダ：x ｜ [≡]
メニュー（≡ で開く）                 画面 ／ 場所 ／ 復旧ドラフト ／ 対応環境の確認 ／ ヘルプ ／ ロック
お知らせの帯（あるときだけ）         新しい版・作業場所の書き出し状態・フォルダや設定の問題・Git の結果
画面                                 ロック解除 ／ 記事（一覧｜編集） ／ Git と同期 ／ 設定
フッター                             復旧ドラフトの設定 ・ 版と更新の確認（最初の画面と、記事フォルダの準備の画面）
```

| 領域 | 中身 | 出す条件 |
|---|---|---|
| 上部バー | アプリ名、いまの画面の名前、開いている場所の名前、メニュー（≡）。説明文は置かない | 常に（同じ大きさで固定） |
| メニュー | 下の「メニューの中身」の項目 | 常に開ける（項目ごとの条件は下の表） |
| ロック解除 | パスキーの登録・回復コードの保存、2 回目からはパスキー（使えなければ回復コード）でのロック解除 | ロックを解除するまで（上部バーとメニューは出したまま） |
| お知らせの帯 | 新しい版の案内、作業場所の書き出し・同期の状態と「書き出す」、フォルダ・設定ファイルの問題、Git の結果（「Git と同期」の外にいるとき） | フォルダ（作業場所）を開いた後、出すものがあるとき |
| 画面「記事」 | 記事一覧、編集。復旧ドラフトの候補は、メニューの「復旧ドラフト」から開く | 記事フォルダがあるとき |
| 画面「Git と同期」 | Git パネル、GitHub との同期 | 同上 |
| 画面「設定」 | 版と更新の確認、復旧ドラフトの設定（既定で有効）、ロック解除（パスキーの登録）、自動ロック（ブラウザ内の作業場所を開いているとき） | 同上 |
| フッター | 復旧ドラフトの設定（畳む）、版と更新の確認 | 最初の画面と、記事フォルダの準備の画面 |

- 「Git と同期」「設定」は文章と入力欄が中心なので、幅を 48rem に絞って中央に置く。

### メニューの中身

| 項目 | 中身 | 出す条件 |
|---|---|---|
| 画面 | 記事・Git と同期・設定（狭い画面は「一覧」「編集」を分ける）。いまの画面は `aria-current="page"` | フォルダを開いた後 |
| 場所 | 作業場所の一覧に戻る、または別のフォルダを開く | 作業場所を開いているとき（一覧に戻る）、フォルダを開いているとき（別のフォルダを開く） |
| 復旧ドラフト | 退避した未保存の編集の一覧をダイアログで開く。件数を右に出す | ロックを解除した後、復旧ドラフトを使えるとき |
| 対応環境の確認 | ダイアログ。使えないときは「この環境では使えません」と警告の印 | 常に |
| ヘルプ | ダイアログ | 常に |
| ロック | ロック解除の画面に戻す。ブラウザ内の作業場所は、ロックを解除するとまた開ける | ロックを解除した後 |

- 自動ロックも、ロック解除の画面に戻す。
- メニューの「ロック」と対になる操作は「ロック解除」と呼ぶ。見出しは「ロック解除」、ボタンは「パスキーでロック解除」（[ADR-0014](../decisions/0014-lock-unlock-wording-and-no-backward-compat.md)）。

### 開閉の印

開閉のボタン（≡）の右上に点を出す。警告（この環境では使えない）は危険の色、情報（未確認の復旧ドラフトがある）はアクセントの色。点だけに頼らず、ボタンの説明（`aria-describedby`）で同じことを伝える。

## 画面の切り替え

- 上部バーの「メニュー」（`aria-expanded`・`aria-controls`）で開く `<nav aria-label="メニュー">` の中のボタン。いまの画面は `aria-current="page"`。見た目は**文字の太さと左の線**で示し、色だけに頼らない（仕様 14.1）。
- 開くと最初の項目へフォーカスを移す。Esc・外側の押下・項目の選択で閉じ、開閉のボタンへ戻す。
- 広い画面：「記事」「Git と同期」「設定」。狭い画面：「一覧」「編集」「Git と同期」「設定」。使わない方は `display: none` で、読み上げにも出さない。
- 「編集」は記事を開いていないとき押せない。一覧で記事を開くと「編集」に移る。記事を閉じる・削除すると「一覧」に戻る。
- フォルダ（作業場所）を開き直すと「記事」（狭い画面では「一覧」）に戻る。

### ダイアログ

- 「対応環境の確認」「復旧ドラフト」「ヘルプ」は、メニューから開く窓（ダイアログ）。閉じると、開閉のボタン（≡）へフォーカスを戻す。
- 30rem 以下では、どのダイアログも画面の下から出すシートになる（[デザインシステム](design-system.md) の「シート」）。
- 「復旧ドラフト」は、閉じている間も件数を数える。件数はメニューの右に出す。

### フォーカスと通知

- ロック解除の画面が消えたら、画面の中身（`main`）へフォーカスを移す。
- Git の結果（コミットした・できなかった）は「Git と同期」の画面の先頭に出す。その画面を見ていないときは、お知らせの帯に1行で出し、「「Git と同期」で見る」と「閉じる」を付ける。
- スキップリンク「本文へ移動」は `main` へ移る（変更なし）。

## 狭い画面と iPhone・iPad

| 幅 | 上部バー | 画面 |
|---|---|---|
| 60rem より広い | 1 行：アプリ名・いまの画面・場所・メニュー | 画面の高さに固定し、領域ごとにスクロール |
| 30rem〜60rem（iPad の縦など） | 同じ 1 行。固定して大きさは変えない | ページ全体でスクロール。一覧と編集は1度に1つ |
| 30rem 以下（iPhone の縦） | 1 行：アプリ名・いまの画面・メニュー（場所の名前は外す） | 同上 |

- 指で押せる大きさは、どの部品も 44px 以上。入力欄の文字は 16px 以上（[デザインシステム](design-system.md) の「指の画面」、[ADR-0015](../decisions/0015-iphone-17-safari-first-ui.md)）。
- 固定した上部バーの下にフォーカスした部品が隠れないよう、狭い画面では `scroll-padding-top` に上部バーの高さを足す。下の操作バーとキーボードの分は `scroll-padding-bottom` に足す。
- 画面の端まで使う（`viewport-fit=cover`）。上部バーは上と左右、画面の中身は左右、下の操作バーとフッターは下の安全領域（`--safe-*`）を余白に足す。ブラウザの枠の色（`theme-color`）は上部バーの面の色に合わせる。
- メニューは、30rem 以下では画面の幅いっぱいに開く。

### 狭い画面の編集画面

```
上部バー（固定）          Kotono CMS ｜ 記事・編集 ｜ [≡]
記事名・状態の印          記事名（2 行まで） ／ 保存・原稿・Git（1 行。あふれたら横に送る）
タブ（上部バーの下に固定）  本文 ｜ 記事情報 ｜ Markdown ｜ プレビュー
中身                      選んだタブの中身だけ
書式の帯（下に固定）       見たまま編集にフォーカスがある間だけ。操作バーの上
下の操作バー（下に固定）    [ 保存 ] [元に戻す] [やり直す] […]
（画面キーボード）         出ている間は、操作バーと書式の帯がその上に載る
```

- 広い画面の「フォーム」（本文と記事情報を横に並べる）を、狭い画面では「本文」と「記事情報」のタブに分ける。新しい記事は「記事情報」から、既存の記事は「本文」から始める。
- 「…」（原文の退避・その他）には、広い画面の操作列にある「コミット…」「削除…」「閉じる」（ここでは「記事を閉じる」）も入れる。メニューは上へ開く。
- 見たまま編集の書式の帯は、指の画面では画面の下に付ける。マウスの画面ではカーソルの近くに浮かせる（[ADR-0011](../decisions/0011-passkey-first-and-compact-ui.md) のまま）。
- 通知（トースト）は上部バーのすぐ下に出す。下は書式の帯・操作バー・キーボードが使う。
- 作業場所の書き出しの帯は、30rem 以下では文を左、「書き出す…」を右に置く（1 段）。

## 確かめていないこと

- 実機（iPhone・iPad の Safari、Windows・macOS の Chrome・Edge）での表示。確認はヘッドレス Chromium の 1280×800・900×800・402×874（iPhone 17 相当・タッチ）の画面だけ。
- 実機の画面キーボード・安全領域・iOS 26 の Safari の浮いたツールバーと、下の操作バー・書式の帯の重なり（[ADR-0015](../decisions/0015-iphone-17-safari-first-ui.md) の「確かめていないこと」）。
- メニューとダイアログの VoiceOver での読み上げ。
- 実際の利用者が「Git と同期」「設定」を見つけられるか、また「…」の中の「書き出す」「削除」を見つけられるか（発見性）。
