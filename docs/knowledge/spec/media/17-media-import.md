## 17. メディア取り込み

| 項目 | 仕様 |
| --- | --- |
| 対象 | JPEG・PNG・GIF・WebP・AVIF |
| SVG | 取り込み・プレビュー対象外 |
| 動画・音声・PDF等 | 取り込みUI対象外。既存ファイルは保持 |
| 保存先 | 当該記事のmedia/ |
| 名前 | ランダムID＋内容形式に対応する小文字拡張子 |
| メディアID | Nano ID、安全な乱数、記事IDと同じ文字集合、固定10文字 |
| 同名検査 | 当該保存先の全エントリー。初回を含め最大11候補 |
| 加工 | リサイズ・圧縮・変換・メタデータ除去をしない |
| 容量・画素数・一括数 | 第4章の設定 |
| 処理並列度 | デコード・保存を1ファイルずつ行う |
| alt | 入力可。装飾画像用の空文字を許容 |
| cover | 取り込み済み画像から選択。本文挿入は不要 |

### 17.1 検証・成功確定

- 拡張子や申告MIMEだけでなく内容形式を調べる。拡張子・内容の不一致は拒否する。
- 容量を先に検査し、可能な範囲でヘッダーから画素数を検査してからデコードする。
- 画像として読み込みできることを確認する。形式不正と環境非対応を識別できる場合は区別する。
- アニメーションの全フレーム負荷を画素数制限だけで保証しない。巨大・異常画像で停止しないことを試験し、必要な追加制限を技術ゲートで確定する。
- 同名候補がなくても保存時に存在を再確認し、既存画像を上書きしない。
- ファイルの書き込み・クローズ・再読み込み検証後を取り込み成功とする。
- 成功した画像だけを本文へ挿入できる。本文へ挿入するalt・パスをMarkdown構文に合わせてエスケープする。
- 複数画像は各画像のaltを確認してから挿入する。coverのaltは本文画像とは別に編集できる。
- 元メタデータを保持することを取り込み画面とヘルプに表示する。

### 17.2 一括処理・キャンセル

ファイルごとに未処理・検証中・保存中・成功・失敗・キャンセルを表示する。キャンセルは次のファイル開始前など安全な境界で受け付ける。成功分は保持し、未挿入分も管理画面で確認できる。失敗時に残存ファイルがある場合はパスと状態を明示する。

画像は取り込み成功時点でディスクに存在する。本文編集を破棄しても削除しない。手動で未使用画像を確認・削除できる。

### 17.3 既存画像の表示検証

- 取り込み時の検証済み状態を、外部配置されたファイルへ流用しない。プレビュー・cover・メディア一覧でデコードする前に、存在・実体形式・サイズ・画素・対応形式・固定安全上限を確認する。
- 拡張子偽装、SVG等の非対応形式、異常ヘッダー、上限超過は表示しない。ファイル自体は保持する。
- 検証キャッシュは内容識別子と検証ルール版へ結び付ける。mtime・サイズだけで差替えなしと判断しない。
- 原本保存と表示用処理を分離する。原本を変更せず、必要に応じた縮小表示用資源を生成できる。縮小生成の前段にもデコード予算を適用する。
- 一覧では原寸の大量デコードをしない。重い画像はプレースホルダーと手動表示操作を提供する。
- アニメーションは初期版プレビューで自動再生しない。静止フレームの安全な取得が証明できる場合だけ表示し、できなければプレースホルダーとする。全フレーム展開を検証手段に使わない。
- アニメーションのフレーム数等の固定上限は第34章に従う。環境上測定できない場合に無制限として扱わない。
- 画像リソース・ImageBitmap等の寿命も管理し、オブジェクトURL解放だけをメモリ解放の証拠としない。
