## 2. 対応環境と技術成立性ゲート

### 2.1 対応環境

| 項目 | 仕様 |
| --- | --- |
| ブラウザ | リリース時のデスクトップ版Chrome・Edge安定版のうち、環境表で検証済みの版 |
| OS | Windows・macOS。具体的な版は検証記録とリリースノートで固定 |
| Firefox・Safari・モバイル・その他OS | 初期版の動作保証対象外 |
| 起動 | 単一HTMLの `file://` 起動 |
| ローカルサーバー | 利用者による起動は不要 |
| 配布物 | JS・CSS・フォント・依存ライブラリを含め、外部CDNに依存しない |
| フォルダアクセス | ユーザーによる明示的な選択・権限付与を必要とする |
| 次回起動 | フォルダ選択・権限の永続化を必須としない |

起動時に必要なAPIと権限を確認する。非対応環境では理由を表示して編集を開始しない。必要なフォルダを選べない・必要な読み書きができない場合は、フォルダ再選択・権限付与を案内する。

### 2.2 技術成立性ゲート

UI本実装前に、失敗注入可能な最小プロトタイプで以下を確認する。APIの存在・正常時の成功だけでは合格としない。

| ゲート | 内容 | 合格証拠 |
| --- | --- | --- |
| TG01 | file起動、フォルダ選択、権限拒否・失効、実ファイルの読み書き | 環境別操作記録・前後内容 |
| TG02 | 実フォルダ用fsアダプターとGit初期化・追加・変更・削除コミット | 第31章の意味論表、I/Oトレース、外部Gitの整合性検証 |
| TG03 | Gitメタデータ各書き込み境界での中断と再起動 | HEAD・index・ref・objectの照合、破損・不明の停止記録 |
| TG04 | 新規作成の存在確認競合・所有確認 | APIで証明できる範囲、競合注入試験、非保証の説明 |
| TG05 | シンボリックリンク・ジャンクション等と権限領域境界 | OS別・操作別の観測能力と停止方法 |
| TG06 | 単一ファイルの書き込み・クローズ・再読込失敗 | 基準版・候補版・第三版を識別した記録 |
| TG07 | YAML往復保持と意味的変更判定 | 保持フィクスチャ・同値比較表 |
| TG08 | プレビューの隔離・URL・パス・外部通信禁止 | 権限到達試験、通信記録、CSP試験 |
| TG09 | 解析・画像・再帰・Git・設定・マニフェスト・ログ・列挙結果の資源予算と中断 | 第34.5節の数値承認・入口別対応表、構築中の制限、予算超過時もUI・退避が使える記録 |
| TG10 | ブラウザ内復旧ドラフト | file起動での保存・再起動復旧・破損・容量不足・更新後の試験 |
| TG11 | 削除前退避と完成マーカー方式 | 別領域への退避検証、途中中断、未確認削除防止 |
| TG12 | 性能・日本語IME・アクセシビリティ | 第25・26・34章の測定と操作試験 |

Chrome・Edge、Windows・macOSを分けて記録する。不成立なら、対象環境・起動方式・保証・機能範囲を再合意する。単に警告を出す、既知の制限へ移す、Gitや復旧機能を黙って削ることでは合格にならない。

ブラウザ更新後は起動時の能力検査を行う。ただし能力検査は実機試験の代替ではない。新しい安定版は優先して回帰試験し、検証済み版・未検証版を区別して表示する。未知版を検証済みと称さない。既知の重大な保存・Git障害がある組み合わせでは該当書き込みを止め、理由と退避方法を示す。
