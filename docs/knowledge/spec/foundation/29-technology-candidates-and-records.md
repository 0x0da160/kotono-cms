## 29. 技術候補とリリース前の確定記録

### 29.1 技術候補

- ファイルアクセス：File System Access APIのshowDirectoryPicker等。
- Git：isomorphic-gitと実フォルダ用fsアダプター。
- YAML：文書ノード・コメント・トークンを保持できるパーサー。
- Markdown：参照抽出と描画で同じ構文解析系を共有できる実装。
- 外部変更比較：内容比較、または暗号学的ハッシュと存在確認。
- 重い処理：Worker・分割処理・上限付きキュー。

Nano ID以外のライブラリは、採用・版・設定を技術ゲートで固定する。ライブラリ採用は本仕様の安全性保証を代替しない。

### 29.2 必ず埋める技術記録

| 記録 | 必須内容 |
| --- | --- |
| 環境表 | OS・ブラウザ版・API可否・権限・file起動の実測 |
| fsアダプター設計 | 対応メソッド、エラー、パス制約、書き込み・排他・属性の意味、実現不能・近似・実現済みの区別、I/Oトレース |
| Git互換性表 | 対応形式・属性・無視規則・改行・フック・署名・特殊構成の判定と停止方法 |
| 保存安全性 | クローズ・再読込・部分失敗・中断・再試行の実測 |
| YAML保持表 | パーサー版・設定・対応構文・保持フィクスチャ |
| 描画安全性 | URL・パス・許可要素・CSP・外部通信試験 |
| 性能付表 | データセット、環境、測定手順、承認済み合格値 |
| 配布物 | アプリ版、仕様版、依存一覧、ライセンス、既知の制限 |

### 29.3 アプリ更新と互換性

配布HTMLにアプリバージョン・仕様バージョンを表示する。自動更新しない。記事や設定の破壊的な自動移行は行わない。将来の形式変更は移行仕様・確認・退避方法を別途定義する。依存ライブラリ更新後も保持・安全性・相互運用試験を再実行する。

### 29.4 配布物の真正性・依存管理

- 正式配布元と、その配布元をユーザーが識別する方法をリリース資料へ記載する。
- HTML成果物の暗号学的ハッシュ、依存関係の固定版・ロック情報・ライセンス・ビルド手順を提供する。ハッシュを配布物と同じ場所に置くだけで配布元の真正性まで証明したと説明しない。
- 署名または別経路の検証情報を提供し、正式リリースとの対応を確認できるようにする。具体方式は出荷前に確定する。
- 再現可能ビルドを目標に差分原因を記録する。未達でも成果物の真正性確認と依存固定は必須。
- 自動更新・自動通信をせず、ユーザーが明示的に開くリリースノート／セキュリティ告知先を提供する。重大な脆弱性では影響版・対処・データ保全手順を告知する。
- 依存ライブラリやサニタイザー等の更新後は、保持・資源制限・描画隔離・Git相互運用の回帰試験を行う。
