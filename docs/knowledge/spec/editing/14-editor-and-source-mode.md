## 14. エディタ・原文モード

- frontmatterフォーム、Markdownソースエディタ、プレビューで構成する。
- リッチテキスト編集は提供しない。
- プレビューは未保存内容を反映する。公開サイトの見た目やURLを保証しない。
- フォームと原文モードは同一の編集中文書を編集し、切り替えだけで保存・破棄しない。
- 原文からフォームへの切り替えで構文・スキーマ検証を行う。失敗したら原文とエラー位置を維持する。
- 未知フィールドの専用フォームは作らず、原文で編集する。
- 原文モードでもID・createdAt・updatedAt等の制約は保存時に適用する。
- 構文エラー中は原文の編集・コピー可。保存とフォーム編集は停止する。
- フォーム・原文・本文は単一の正本文書とリビジョン番号を共有する。各モードが独立した古い本文を正本として持たない。
- フォーム変更と原文変更を文書レベルの共通Undo/Redo履歴へ記録する。IME変換・連続入力等を意味のある単位へまとめ、モード切替自体は内容変更にしない。
- フォーム変更→原文変更→フォーム復帰→Undoでは、最後の原文変更を戻し、フォームの先行変更は維持する。Redoも同一文書へ適用する。
- 保存によってUndoを消去しない。履歴予算超過時の古い履歴の切捨ては通知する。現在文書・保存基準・保存中スナップショットを切り捨てない。
- 原文構文エラー中に最後の正常プレビューを残す場合は「古い版」と表示し、現在の原文を描画したと誤認させない。
- UndoでID・createdAt等を不正に変更できても、保存時の制約は回避できない。
- メタデータフォームの値を本文変更と誤認して本文を再生成しない。

### 14.1 日本語入力・アクセシビリティ

- 日本語IMEのcomposition中に、Enterやショートカットで未確定文字列を失わせない。保存時は変換確定を待つか、明示的に確定を案内する。
- キーボードのみで記事選択、検索、フォーム／原文移動、保存、エラー確認、退避、確認ダイアログ操作を完了できる。
- ラベル、見出し、ランドマーク、フォーカス可視化を提供する。色だけで状態を伝えない。
- モーダルの初期フォーカス、閉じた後の復帰、危険操作の既定選択を定義する。削除を既定のEnter操作にしない。
- 保存結果・失敗・進捗を支援技術へ通知する。頻繁な入力ごとの過剰な読み上げを避ける。
- 200%ズームおよび1280×720相当の表示領域で主要操作を利用可能にする。3ペイン固定を強制せず、単一ペイン切替を提供する。
- WindowsのNVDAとmacOSのVoiceOverを用いて、主要操作フローをそれぞれ検証する。具体版は環境表に記録する。
